# Calculus Simulator (Adv-Cal-sim)

An advanced **Calculus & Math Simulator**: type a function, get its exact symbolic
derivative and antiderivative, see the graphs, and watch differentiation /
integration happen interactively.

The heavy math runs in a **Rust** engine compiled to **WebAssembly**; the UI is
**TypeScript + React (Vite)** with **Plotly.js** for graphing and **KaTeX** for
LaTeX rendering.

---

## Features

- **Symbolic differentiation** — exact derivative with simplification
  (product/quotient/chain rules, trig, inverse-trig, hyperbolic, log/exp, power).
- **Integration** — symbolic antiderivative where a rule matches, plus
  **adaptive Simpson** numerical integration for definite integrals.
- **Plotting** — interactive Cartesian graph of `f(x)`, `f′(x)` and `F(x)`
  (zoom, pan, scroll-zoom), with asymptote gaps handled via NaN.
- **Differentiation simulation** — a point slides along `f(x)` while a tangent
  line updates to show the slope (`f′`) at that point.
- **Integration simulation** — shade the area under `f(x)` between limits `a`
  and `b`, with the live definite-integral value.
- **LaTeX results** rendered with KaTeX (no CDN, fully offline).

## Tech stack

| Layer | Technology |
|-------|------------|
| Frontend | TypeScript, React 18, Vite 6 |
| Graphing | Plotly.js (`plotly.js-dist-min`) |
| Math rendering | KaTeX |
| Math engine | Rust (`calcsim-core`) — custom recursive-descent parser + symbolic CAS-lite |
| Bridge | `calcsim-wasm` via `wasm-bindgen` (`--target web`) |

## Project structure

```
Adv-Cal-sim/
├── Cargo.toml                  # Rust workspace (resolver 2)
├── crates/
│   ├── core/                   # the math engine (no UI deps)
│   │   ├── src/
│   │   │   ├── ast.rs          # expression AST (Expr enum)
│   │   │   ├── parser.rs       # lexer + recursive-descent parser
│   │   │   ├── diff.rs         # symbolic differentiation
│   │   │   ├── integrate.rs    # symbolic table + adaptive Simpson
│   │   │   ├── simplify.rs     # algebraic simplification / canonicalisation
│   │   │   ├── eval.rs         # numeric evaluation
│   │   │   ├── sample.rs       # grid + (x,y) sampling with NaN gaps
│   │   │   ├── render.rs       # ASCII + LaTeX rendering
│   │   │   └── lib.rs          # `process` entry point → Analysis JSON
│   │   └── tests/engine.rs     # integration tests
│   └── wasm/
│       └── src/lib.rs          # wasm-bindgen wrapper → `process(input, x_min, x_max, samples)`
├── web/                        # frontend
│   ├── src/
│   │   ├── engine.ts           # WASM loader + typed client
│   │   ├── App.tsx             # main UI + simulation logic
│   │   ├── Plot.tsx            # Plotly wrapper
│   │   ├── Katex.tsx           # KaTeX renderer
│   │   └── wasm/               # generated by build-wasm.sh (gitignored)
│   ├── index.html
│   ├── package.json
│   └── vite.config.ts
└── scripts/
    └── build-wasm.sh           # builds Rust → web/src/wasm
```

### Data flow

```
User types f(x)
   └─▶ engine.analyze()  (web/src/engine.ts)
         └─▶ WASM process(input, x_min, x_max, samples)   [Rust]
               ├─ parse → AST
               ├─ diff / integrate (symbolic + numerical)
               ├─ sample f, f′, F over the grid
               └─▶ JSON Analysis { xs, ys, dys, fs, latex, definite_value, ... }
                     └─▶ React state → Plotly traces + KaTeX results
```

## Prerequisites

- **Rust** (stable, e.g. 1.85+) with the `wasm32-unknown-unknown` target:
  ```bash
  rustup target add wasm32-unknown-unknown
  ```
- **wasm-pack** (bundles `wasm-bindgen` and `wasm-opt`):
  ```bash
  curl https://rustwasm.github.io/wasm-pack/installer/init.sh -sSf | sh
  ```
- **Node.js** 18+ and **npm**.

## Run it

```bash
# 1) (optional) verify the Rust engine
cargo test

# 2) install frontend deps
cd web && npm install

# 3) start the dev server (builds WASM automatically via `predev`)
npm run dev
#    → open the printed URL (default http://localhost:5173)
```

### Production build

```bash
cd web
npm run build      # builds WASM first, then `tsc` + `vite build` → web/dist
npm run preview    # serve the built bundle locally
```

### Rebuild only the WASM

```bash
./scripts/build-wasm.sh
# or, from web/:  npm run build:wasm
```

## Deploy with Docker

The app is published as a **public** Docker image on Docker Hub:
[`rachata2567/calcsim`](https://hub.docker.com/repository/docker/rachata2567/calcsim).

It is a self-contained static site (nginx serving the built React + WASM bundle)
— no backend or reverse proxy required.

### Run the published image

```bash
docker run -d --name calcsim --restart unless-stopped -p 8080:80 rachata2567/calcsim:latest
# → open http://localhost:8080
```

Or with Compose (see `docker-compose.yml`, defaults to the Hub image):

```bash
PORT=8080 docker compose up -d     # port 8080
PORT=80   docker compose up -d     # serve directly on port 80
```

### Build locally (optional)

```bash
docker build -t calcsim:latest .
# or, with `build: .` uncommented in docker-compose.yml:
docker compose up -d --build
```

### Release a new version to Docker Hub

Build and push a **multi-arch** image (`linux/amd64` + `linux/arm64`) so it runs
on both x86 servers and ARM machines. A plain `docker build`/`docker push` would
push only your local architecture — use `buildx` instead:

```bash
docker buildx build --platform linux/amd64,linux/arm64 \
  -t rachata2567/calcsim:latest \
  -t rachata2567/calcsim:0.1.0 \
  --push .
```

## Supported syntax

| Input | Meaning |
|-------|---------|
| `x^2 + sin(x)` | powers, `+ - * / ^` |
| `2x`, `3sin(x)`, `x(x+1)` | implicit multiplication |
| `sin cos tan asin acos atan` | trig |
| `sinh cosh tanh` | hyperbolic |
| `exp(x)` / `e^x` | exponential |
| `ln(x)` / `log(x)` / `log(x, base)` | logarithms |
| `sqrt(x)`, `abs(x)` | root / absolute value |
| `pi`, `e` | constants |
| `pow(a, b)` | power (two-argument form) |

Examples to try: `x^3 - 3*x`, `sin(x)`, `e^x`, `ln(x)`, `1/x`, `x*sin(x)`, `sqrt(x)`.

## Notes

- The antiderivative curve `F(x)` is defined as `∫[x_min, x] f(t) dt`, so the
  shaded area between `a` and `b` is computed as `F(b) − F(a)`.
- Functions with singularities (e.g. `1/x`) render with gaps and their definite
  integral over a singular interval returns `undefined` instead of a wrong value.
- The engine never panics on malformed input — it returns an `ok: false` result
  with a human-readable error, which the UI surfaces in red.
